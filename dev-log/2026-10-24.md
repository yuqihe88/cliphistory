### 1. 修复 `npm run dev` 启动即崩溃的 Bug

- **现象**：`npm run dev:main` 后 Electron 报 `TypeError: Cannot set properties of undefined (setting 'isQuitting')`，即 `require('electron').app` 为 undefined，Electron 以纯 Node.js 模式运行。
- **根因**：`dev:main` 脚本中 `set ELECTRON_RUN_AS_NODE= && electron .` 在 cmd 里**不会删除变量**，而是把它设成一个空格（`set VAR= ` 的尾随空格会成为变量值），非空值即触发 Electron 的 run-as-node 模式。
- **修复**：改为带引号的正确写法 `set "ELECTRON_RUN_AS_NODE="`，该写法会真正删除变量。
- **修改文件**：`package.json`

### 7. 修复图片不显示 + 图片文件识别 + 真文件回写

**问题一：复制的图片在应用里不显示（两个叠加 Bug）**
- 位图图片（网页"复制图片"）其实已被捕获保存，但卡片用 `file://` 加载本地图片：开发模式页面跑在 `http://localhost:5173`，Chromium 禁止 http 页面加载 file:// 资源 → 永远显示不出来
- 修复：注册自定义协议 `clipimg://local/<encodeURIComponent(绝对路径)>`（`protocol.registerSchemesAsPrivileged` + `protocol.handle`，仅放行图片扩展名），CSP `img-src` 加入 `clipimg:`，`ClipCard` 改用该协议加载 → 开发/生产模式统一可显示 ✅（截图已验证缩略图渲染）

**问题二：复制本机图片文件被当成文字路径记录**
- 复制图片文件时剪贴板是 CF_HDROP/FileNameW（文件）而非位图，原先落到文字分支
- 修复：`checkFileClipboard` 按扩展名分流——视频 → `video` 记录；图片（.png/.jpg/.jpeg/.gif/.bmp/.webp）→ `image` 记录，`imagePath` 引用原文件（限制 50MB）；并抑制文字路径重复入库 ✅（E2E：icon.png → `type=image` 记录 + 日志确认）

**问题三：视频回写的只是路径文本，用户要"真正的文件"**
- Electron 无写 CF_HDROP（文件剪贴板）的原生 API；引入 `writeFileToClipboard()`：调用系统 `powershell Set-Clipboard -LiteralPath`（无窗口、5s 超时），实现点击卡片回写**真实文件**（可在资源管理器/聊天窗口直接粘贴出文件本体）
- 视频记录、图片文件记录均走该通道；位图记录仍回写位图。回写成功后同步更新 `lastVideoPath`/`lastImageFilePath`/`lastImageHash`/`lastTextHash`，防止回写内容被自家监听器再次捕获成新记录
- `writeToClipboard` 改为 async，IPC handler 相应 await

**配套加固**
- 删除保护：`deleteRecord` / `cleanupOldRecords` / `clearAll` 只允许删除 `imagesDir` 内的应用自管理文件，绝不删除用户原始文件
- 图片记录按 `image_path` 去重（重复复制同一文件/重启后不再重复入库）
- 已知局限：`FileNameW` 仅在复制**单个**文件时由系统合成，多选文件复制不会记录；网页图片若浏览器只提供 HTML 片段（右键"复制图片"才行）则捕获不到

- **实现**：
  - 手动拖拽方案（图标窗口 movable=false，不走 app-region）：DockIcon 用 **Pointer Capture**（`setPointerCapture`）跟踪指针——小窗口只有 44×84，普通 mousemove 一出窗口就丢事件，指针捕获保证拖出范围仍持续收到 move
  - 渲染进程发屏幕坐标 → 主进程 `DOCK_DRAG_START/MOVE/END`：x 固定贴边、y = 起点纵坐标 + 增量（夹取），`getDisplayNearestPoint` 按光标位置自动换边
  - END 时 `moved=false` 走 restoreFromDock，`moved=true` 仅更新位置（preSnapBounds 不变，还原逻辑不受影响）
  - dock 页面设置 `document.title = 'ClipHistory Dock'`（BrowserWindow title 会被页面标题覆盖，此前 Win32 FindWindow 验证找不到就是这原因）
- **顺带修复**：应用启动时未恢复已保存的悬浮模式 → ready 序列读取 floatMode 并 setFloatMode(true)
- **验证**：日志 `drag end: moved=true pos=(2,308)`（拖动生效、吸附左缘）→ 点击后 `moved=false` → 主窗口还原可见 ✅

### 15. 修复拖动图标时主进程崩溃弹窗（TypeError: setBounds conversion failure）

- **现象**：拖动贴边小图标时弹出「A JavaScript error occurred in the main process — Uncaught Exception: TypeError: Error processing argument at index 0, conversion failure from … at BrowserWindow.setBounds ← dock.js:236」
- **根因**：`DOCK_DRAG_MOVE` IPC 处理器直接把渲染进程传来的坐标计算结果交给 `setBounds`，无任何校验；坐标链路中出现 NaN/undefined（疑似指针事件在窗口状态切换瞬间的异常值）即抛 TypeError，且处理器无 try/catch，异常升级为崩溃弹窗
- **修复（纵深防御）**：
  - `validPoint()` 严格校验：x/y 必须为有限数字，否则丢弃该次事件并重置拖动状态
  - 坐标计算结果 `Math.round` 取整 + `Number.isFinite` 终检，不合法直接跳过
  - dock 全部 5 个 IPC 处理器包 try/catch，异常只记日志
  - **主进程全局拦截**：`process.on('uncaughtException'/'unhandledRejection')` 记日志不弹框——桌面工具不允许任何单点异常炸出崩溃弹窗
- **验证**：从渲染进程注入 NaN / 缺字段 / undefined / ±Infinity 坐标 → 全部被拦、应用存活（getSettings 正常响应）；合法拖动仍生效（图标移至新位置）✅

### 16. 图标拖动丝滑化（插值跟随动画）

- **原问题**：每次 pointermove 直接 IPC → setBounds，事件突发 + 往返延迟导致图标一顿一顿地"追"鼠标
- **优化（两层）**：
  - 渲染端：`requestAnimationFrame` 合并坐标——每帧最多发一次 IPC，自动丢弃帧内抖动
  - 主进程：拖动期间跑 16ms 插值动画（lerp 0.35），窗口位置逐帧逼近目标，到位自动停帧；DRAG_END 时吸附到最终位置；还原/异常时统一清理动画帧
- **验证（真实系统级鼠标事件，Win32 SetCursorPos+mouse_event 模拟人手 10 步拖动 150px）**：图标 Top 438→288，精确跟随 150px，无越界 ✅
- 附：BrowserWindow title 会被页面 document.title 覆盖，dock 页面已显式设为 'ClipHistory Dock'

### 17. 图标拖动改为"自由跟手，松手贴边"

- **原行为**：拖动时图标钉在边缘只能纵向滑动
- **新行为**：拖动过程中图标**自由跟随鼠标**（2D 跟手，不贴边）；松手瞬间按图标中心到左/右可用区边缘的距离取近者，**插值滑入**对应边缘（吸附高度 = 松手时高度）
- **实现**：DRAG_START 记录抓取偏移（保证跟手不跳位）；DRAG_MOVE 只更新自由目标位置（夹在屏幕可用区内）；DRAG_END 换算最近边缘 → 设为插值目标 → 动画滑入后自动停帧
- **验证（CDP 模拟拖到屏幕中部松手）**：`release: snap to left edge at (2,498)`，吸附高度跟随松手位置 ✅

### 18. 消除图标拖动延迟（1:1 跟手）

- **原问题**：用户反馈拖动跟随有延迟——根源是拖动期也走 16ms 插值动画（lerp 0.35，尾巴约 100ms）+ 渲染端 rAF 缓冲再发 IPC，双重延迟叠加
- **修复**：
  - 拖动跟随改为**直接 setBounds**（每次 DOCK_DRAG_MOVE 立即应用，零插值零缓冲，1:1 跟手）
  - 渲染端去掉 rAF 缓冲，pointermove 到了就发（Chromium 本身已按帧率合并事件）
  - **插值动画只保留在松手后滑向边缘的吸附段**（那是刻意的缓动动画，不是跟踪）
  - DRAG_START 仍会停掉未完成的贴边动画（用户中途抓住图标即刻接管）
- **验证（Win32 真实鼠标事件拖动 150px）**：图标 Top 438→288，精确 1:1 跟随 ✅

### 19. 修复：图标拖到另一边后，点击还原的窗口位置错误

- **现象**：把图标从左边缘拖到右边缘后点击还原，主窗口却出现在旧的左侧位置
- **根因**：还原位置用的是 `preSnapBounds`——首次贴边前保存的旧坐标，图标被拖到另一边后该记录已过期；且边（dockEdge）已更新为新边，旧坐标 + 新边的偏移钳制后仍落在旧侧
- **修复**：`restoreFromDock` 改为**以图标当前位置为基准**计算还原位置——窗口始终在图标内侧展开（左缘图标 → 窗口在其右侧，右缘图标 → 在其左侧），纵向对齐图标中心并夹回可用区；删除已无用的 `preSnapBounds` / `RESTORE_OFFSET`
- **验证（还原用户操作路径）**：窗口贴左缘 → CDP 拖图标横穿屏幕到右缘（`release: snap to right edge at (1661,458)`）→ 点击图标 → 主窗口 L=1230、T=220（贴着右缘图标内侧、纵向对齐）✅
